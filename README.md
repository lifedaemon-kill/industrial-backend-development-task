в связи с CPU-Bound спецификой задачи, нет смысла создавать больше, чем 8 горутин одновременно,
поэтому я добавил значение maxprocs в стратегию, которое позволир разбить более равномерно не более 8 задач на одно поколение, 
однако по условию на задачу тратится и иметация этого процесса с помощью time.Sleep является i/o bound задачей,
а значит, что увеличенное количество горутин позволит обойти это ограничение, тк они смогу сразу сломать счетчик,
на выходе показав более быстрое время
